# دادهٔ آزمایشی

| فایل | چیست |
|---|---|
| `sagasample.csv` | خروجی واقعی مجموعهٔ تولید (۱۳۵ سند، ۱۱۶ ستون). **فقط برای فهمیدن ساختار رایج** استفاده شده؛ برنامه به این schema وابسته نیست. |
| `es-samples/` | پنج نمونهٔ لاگ با ساختار Elasticsearch از فاز قبلی — schema متفاوت، عمداً نگه داشته شده تا اثبات شود همان کد با دو شکل مختلف کار می‌کند. |
| `fixtures.json` | ساخته می‌شود، در بسته نیست. |

## ساخت `fixtures.json`

```bash
python3 tools/build_fixtures.py
```

نتیجه: ۱۵۴ سند از سه schema متفاوت —

- ۱۳۵ سند از CSV بالا (شکل واقعی MongoDB)
- ۵ سند با ساختار Elasticsearch (نام‌های متفاوت، زمان به‌صورت epoch)
- ۱۴ سند **عمداً خراب**: آرایهٔ `null`، عمق ۲۵ لایه، JSON ناقص، رشتهٔ
  یک‌مگابایتی، فیلد حاوی رمز، پنج نمایش مختلف زمان، نوع‌های غیرمنتظره،
  سند خالی، و ارجاع حلقوی.

این ۱۴ سند آخر مهم‌ترین بخش‌اند: کل ادعای «هیچ لاگی برنامه را نمی‌شکند»
روی آن‌ها سنجیده می‌شود.

## اجرای راستی‌آزمایی

```bash
python3 tools/build_fixtures.py && python3 tools/verify_generic.py
```

## سرور ساختگی برای توسعهٔ رابط کاربری

بدون نیاز به MongoDB واقعی (روی `mongomock`):

```bash
python3 tools/mock_api_server.py 8080
cd frontend && npm run dev
```
