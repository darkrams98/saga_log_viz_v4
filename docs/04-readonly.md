# ۴ — تضمین‌های ایمنی: فقط خواندن، و فقط یک پرس‌وجو

این نسخه دو ادعا دارد که هر دو قابل بررسی‌اند:

1. **هیچ‌وقت نمی‌نویسد.**
2. **هیچ‌وقت کل مجموعه را نمی‌خواند** — و برای نمایش یک لاگ، دقیقاً یک
   پرس‌وجو می‌زند.

---

## ادعای اول: فقط خواندن

### لایهٔ ۱ — زمان کامپایل: امکانش وجود ندارد

- `pom.xml` عمداً **`spring-boot-starter-data-mongodb` را ندارد**.
  `MongoTemplate` متدهای `save`/`remove`/`insert` دارد؛ صرفِ بودنش روی
  classpath یعنی هر auto-configurationی می‌تواند بنویسد.
- تنها دروازهٔ پایگاه داده `mongo/LogCollection.java` است و کل متدهای
  عمومی‌اش این پنج تاست:

  ```
  find, findOne, estimatedTotal, listIndexes, connectionInfo
  ```

  نوشتن در این پروژه یک **خطای کامپایل** است، نه یک اشتباه زمان اجرا.

### لایهٔ ۲ — زمان اجرا: نگهبان درایور

`mongo/ReadOnlyGuard.java` یک `CommandListener` است و روی خود درایور
می‌نشیند. هر دستوری که از هر جای برنامه به MongoDB برود از اینجا رد
می‌شود — چه از کد ما، چه از یک کتابخانه، چه از کدی که فردا اضافه شود.

روش **فهرست مجاز** است، نه فهرست ممنوع: ۲۹ دستور خواندنی، و هر چیز دیگری
`ReadOnlyViolationException` می‌گیرد.

> چرا فهرست مجاز؟ چون فهرست ممنوع همیشه از واقعیت عقب می‌ماند. اگر MongoDB
> فردا دستور نوشتن تازه‌ای اضافه کند، فهرست ممنوع آن را نمی‌شناسد؛ فهرست
> مجاز خودبه‌خود ردش می‌کند.

نگهبان `aggregate` را هم بررسی می‌کند و اگر pipeline شامل `$out` یا `$merge`
باشد ردش می‌کند — هرچند در این نسخه اصلاً aggregation اجرا نمی‌شود.

`MongoClientConfig` هم `retryWrites(false)` می‌گذارد.

### لایهٔ ۳ — پایگاه داده: کاربر با نقش `read`

سه لایهٔ بالا در کد ما هستند. این یکی نیست، و برای همین مهم‌ترین است:

```javascript
db.getSiblingDB("admin").createUser({
  user: "log_viewer_ro",
  pwd: passwordPrompt(),
  roles: [ { role: "read", db: "saga" } ]
})
```

بررسی:

```bash
mongosh "$MONGO_URI" --eval 'db.sagaSequence.insertOne({x:1})'
# باید رد شود: not authorized on saga to execute command insert
```

**در استقرار تولید حتماً استفاده‌اش کنید.** این تنها لایه‌ای است که به کد
ما اعتماد نمی‌کند.

## ادعای دوم: بدون پویش، و فقط یک پرس‌وجو

### aggregation و شمارش حذف شده‌اند — نه غیرفعال، بلکه ناموجود

نسخهٔ قبلی `aggregate()`، `sample()` و `countDocuments()` داشت (برای
داشبورد و نمودارها). همه حذف شدند:

```java
// ------------------------------------------------- عمداً وجود ندارند
//  aggregation و شمارش، ذاتاً روی کل collection کار می‌کنند. با نبودشان
//  در این کلاس، اجرای‌شان دیگر یک تصمیم زمان اجرا نیست — یک خطای کامپایل
//  است. پایش کلی کار Grafana است و جستجوی گسترده کار ELK.
```

هیچ endpointی هم برای فهرست، آمار یا نمودار وجود ندارد.

### شمارندهٔ پرس‌وجو

ادعای «بعد از یافتن لاگ، بیش از یک find اجرا نمی‌شود» را نمی‌شود با حرف
اثبات کرد. پس `mongo/OperationCounter.java` تعداد واقعی را می‌شمارد و در
پاسخ API برمی‌گرداند:

```bash
curl -s http://localhost:8080/api/v1/log/42a1e47ccf774a759c841f5ff46e1806 \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print(d["mongoOperations"], d["operations"])'
# 1 ['findOne']
```

همین عدد در کارت خلاصهٔ UI هم نشان داده می‌شود («پرس‌وجوهای MongoDB: ۱ —
مطابق قید طراحی»). یعنی کاربر بدون خواندن کد می‌تواند ببیند.

پیاده‌سازی با `ThreadLocal` است چون Spring MVC هر درخواست را روی یک نخ
اجرا می‌کند؛ پس عدد دقیق است، نه تقریبی.

### جستجوی عادی هرگز اسکن نمی‌کند

فقط روی فیلدی که در `config.json` هم `enabled` است و هم `indexed`.
`IndexInspector` این ادعا را با `listIndexes` راستی‌آزمایی می‌کند و اگر
دروغ باشد، در راه‌اندازی و در `/meta/health` هشدار می‌دهد.

### جستجوی پیشرفته کران‌دار است

سقف تعداد، سقف زمان سمت سرور، و **بدون `sort`** — چون sort روی فیلد بدون
ایندکس یا حافظه را پر می‌کند یا سرور را وادار به اسکن کامل می‌کند.

## یک اشکال واقعی که همین‌جا پیدا شد

هنگام راستی‌آزمایی، یک سند آزمایشی با رشتهٔ ۳۰۰ کیلوبایتی، پردازش را
**بیش از دو دقیقه** قفل کرد. علت، الگوی ماسک متن آزاد بود:

```java
// قبل — نام فیلد بی‌کران
"\"?([A-Za-z_][A-Za-z0-9_]*)\"?\\s*[:=]\\s*\"([^\"]{1,64})\""
```

روی رشته‌ای بدون جداکننده (مثلاً یک payload کدشدهٔ base64 داخل
`commandContent`) این الگو رفتار **درجه‌دو** پیدا می‌کند: موتور regex از هر
موقعیت تا انتهای رشته پیش می‌رود و شکست می‌خورد.

اندازه‌گیری:

| ورودی | الگوی بی‌کران | الگوی کران‌دار |
|---|---|---|
| ۲۰ کیلوبایت | ۶٫۹ ثانیه | — |
| ۳۰۰ کیلوبایت | ~۲۶ دقیقه (تخمین) | **۰٫۷ ثانیه** |

اصلاح، یک کران روی نام فیلد بود (نام فیلد بلندتر از ۶۵ نویسه در عمل وجود
ندارد) به‌علاوهٔ یک سقف کلی روی پویش متن آزاد:

```java
"\"?([A-Za-z_][A-Za-z0-9_]{0,64})\"?\\s*[:=]\\s*\"([^\"]{1,64})\""
```

نتیجهٔ تطبیق دقیقاً همان است. این مورد روی یک سرویس فقط-خواندنی که
payloadهای دلخواه تولید را می‌خواند، یک **منع سرویس از راه داده** بود.
بررسی شمارهٔ ۳۸ در `verify_generic.py` جلوی بازگشتش را می‌گیرد.

## چطور خودتان بررسی کنید

### ۱) راستی‌آزمایی خودکار

```bash
python3 tools/build_fixtures.py && python3 tools/verify_generic.py
```

بخش‌های ۵ و ۶ همین ادعاها را می‌سنجند:

```
✅ نمایش کامل یک لاگ فقط یک پرس‌وجو لازم دارد
✅ جستجوی عادی فقط روی فیلدهای ایندکس‌شده باز است
✅ هیچ فراخوانی نوشتنی در کد جاوا نیست
✅ هیچ aggregation یا پویش کل مجموعه‌ای در کد نیست
✅ دروازهٔ داده هیچ متد نوشتن یا پویش ندارد
✅ هیچ endpoint داشبورد یا فهرست لاگ‌ها وجود ندارد
✅ الگوی ماسک متن آزاد کران‌دار است
```

### ۲) تست‌های JUnit

```
backend/src/test/java/…/mongo/ReadOnlyGuaranteeTest.java
  ├─ فهرست مجاز هیچ دستور نویسنده‌ای ندارد
  ├─ ۳۰ دستور نویسنده در زمان اجرا مسدود می‌شوند
  ├─ دستور ناشناخته هم مسدود می‌شود
  ├─ aggregate با $out یا $merge مسدود می‌شود
  ├─ LogCollection هیچ متد نوشتن ندارد            (reflection)
  ├─ LogCollection هیچ متد پویش کل مجموعه ندارد   (reflection)
  ├─ شمارندهٔ پرس‌وجو دقیق است و بین درخواست‌ها نشت نمی‌کند
  ├─ هیچ فراخوانی نوشتن در کل کد منبع نیست         (پویش فایل)
  └─ Spring Data MongoDB روی classpath نیست        (pom.xml)
```

### ۳) وضعیت زنده

```bash
curl -s http://localhost:8080/api/v1/meta/health
```

`readOnly.blockedWriteAttempts` باید **همیشه صفر** باشد. اگر نیست، یعنی
جایی از برنامه تلاش کرده بنویسد — لاگ سرور را با
`grep "عملیات نوشتن در MongoDB مسدود شد"` ببینید.

---

## آنچه این تضمین‌ها *نمی‌کنند*

- **بار خواندن هنوز واقعی است.** جستجوی پیشرفته می‌تواند به نود فشار
  بیاورد. برای همین `readPreference: secondaryPreferred` و `maxTimeMS`
  گذاشته شده — ولی «فقط خواندن» به معنای «بی‌ضرر» نیست.
- **ماسک در لایهٔ نمایش انجام می‌شود، نه در پایگاه داده.** هر کسی به خود
  MongoDB دسترسی داشته باشد، دادهٔ خام را می‌بیند.
- **این سرویس دربارهٔ نگهداشت داده تصمیمی نمی‌گیرد.**
