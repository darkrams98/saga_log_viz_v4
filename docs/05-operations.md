# ۵ — استقرار، استفاده و عیب‌یابی

---

## راه‌اندازی

### پیش‌نیازها

- Java 21، Node.js 20+
- دسترسی خواندن به MongoDB

### ۱) کاربر فقط-خواندنی (توسط DBA، یک‌بار)

```javascript
db.getSiblingDB("admin").createUser({
  user: "log_viewer_ro",
  pwd: passwordPrompt(),
  roles: [ { role: "read", db: "saga" } ]
})
```

### ۲) بررسی ایندکس‌ها

```bash
mongosh "mongodb://…/saga" ops/indexes.js
```

انتظار: `✔ ایندکس _id موجود است — کار دیگری لازم نیست.`
این نسخه در حالت عادی **هیچ ایندکس تازه‌ای نمی‌خواهد**.

### ۳) backend

```bash
export MONGO_URI="mongodb://log_viewer_ro:***@host:27017/saga?authSource=admin&readPreference=secondaryPreferred"
export MONGO_DB=saga
export MONGO_COLLECTION=sagaSequence

cd backend && mvn spring-boot:run
```

مسیر فایل‌های پیکربندی:

```bash
java -Dlogexplorer.config=/etc/log-viewer/config.yaml \
     -Dlogexplorer.labels=/etc/log-viewer/config.json \
     -jar app.jar
```

### ۴) frontend

```bash
cd frontend && npm install && npm run build   # → dist/
```

`dist/` را با هر وب‌سروری سرو کنید و `/api` را به backend پروکسی کنید.
برای توسعه: `npm run dev` روی `:5173`.

### ۵) بررسی سلامت

```bash
curl -s http://localhost:8080/api/v1/meta/health | python3 -m json.tool
```

| کلید | مقدار درست |
|---|---|
| `mongo.reachable` | `true` |
| `readOnly.blockedWriteAttempts` | `0` |
| `searchFields.problems` | `[]` |
| `configWarnings` / `labelWarnings` | `[]` |

## استفادهٔ روزمره

### مسیر اصلی

1. پشتیبان در **ELK** فرایند مشکل‌دار را پیدا می‌کند و `_id` را کپی می‌کند.
2. در این ابزار می‌چسباند و Enter می‌زند.
3. **نمای شماتیک** نشان می‌دهد فرایند از کجا شروع شد، به کدام سرویس‌ها
   رفت، و کدام مرحله قرمز است.
4. کلیک روی گرهٔ قرمز → متن خطا، ورودی درخواست، خروجی پاسخ.
5. اگر لازم شد: **نمای جدولی** برای جستجو در همهٔ فیلدها، یا **JSON خام**
   برای کپی کامل.

> کادر جستجو هنگام چسباندن، گیومه و `ObjectId(...)` اضافه را خودش پاک
> می‌کند — چون کپی از ELK معمولاً این‌ها را همراه دارد.

### اشتراک‌گذاری

شناسه در آدرس صفحه است:

```
http://log-viewer/log/42a1e47ccf774a759c841f5ff46e1806
```

پس می‌شود لینک را مستقیم برای همکار فرستاد.

### وقتی شناسه در دست نیست

بخش **جستجوی پیشرفته** را باز کنید. با یک هشدار صریح شروع می‌شود، چون
واقعاً گران است. مثال:

```
commandList.rollbackDescription   شامل متن   Exception
```

حداکثر ۲۰ نتیجه برمی‌گردد؛ روی هرکدام کلیک کنید، همان لاگ باز می‌شود.

## عیب‌یابی

### «لاگی با این شناسه پیدا نشد»

به ترتیب احتمال:

1. **فاصله یا نویسهٔ اضافه** هنگام کپی — شایع‌ترین علت.
2. **نوع `_id` فرق دارد.** اگر مجموعهٔ شما `ObjectId` ذخیره می‌کند و
   ورودی رشته است، نتیجه صفر است بدون هیچ خطایی. در `config.json`:

   ```json
   { "field": "_id", "type": "objectId" }
   ```

   مقدار `auto` (پیش‌فرض) اگر ورودی ۲۴ نویسهٔ hex باشد خودش ObjectId
   می‌سازد؛ برای شناسه‌های ۳۲ نویسه‌ای رشته می‌ماند.
3. لاگ هنوز به MongoDB نرسیده، یا بر اساس سیاست نگهداشت حذف شده.

### گراف خالی است

پیام زیر گراف را بخوانید. سه حالت رایج:

| پیام | یعنی |
|---|---|
| «فیلد commandList در این لاگ وجود ندارد» | این لاگ مرحله ندارد — طبیعی است |
| «فیلد commandList آرایه نیست (string)» | ساختار عوض شده؛ `graph.source` را در config بررسی کنید |
| «مرحلهٔ N شیء نبود» | یک عنصر خراب رد شد؛ بقیه رسم شده‌اند |

در هر سه حالت، **نمای جدولی و JSON خام کامل‌اند**.

### نام میکروسرویس به انگلیسی است

یعنی `routingKey` هنوز در `config.json` ترجمه نشده. سه گام در
[۳ — راهنمای پیکربندی](03-configuration.md#-افزودن-یک-میکروسرویس-جدید).

### همه چیز کند است

1. اگر «جستجوی پیشرفته» باز است، ببندیدش — گران‌ترین حالت است.
2. `POST /api/v1/meta/indexes/inspect` — آیا فیلدی فعال شده که ایندکس ندارد؟
3. `readPreference: secondaryPreferred` را بررسی کنید تا بار روی نود اصلی
   نیفتد.

### کد ملی یا شمارهٔ حساب ماسک شده و برای عیب‌یابی لازم است

```json
"privacy": { "maskingProfile": "secretsOnly" }
```

سپس reload. رمز و توکن در هیچ حالتی نمایش داده نمی‌شوند.

### پیکربندی بعد از reload اعمال نشد

`GET /api/v1/meta/health` را ببینید. اگر فایل خراب باشد، سرویس عمداً
**نسخهٔ سالم قبلی** را نگه می‌دارد و دلیل را در `labelWarnings` می‌نویسد.
JSON کامنت ندارد — کاماهای اضافی شایع‌ترین اشتباه‌اند:

```bash
python3 -c "import json; json.load(open('config/config.json')); print('معتبر')"
```

## مهاجرت از نسخهٔ داشبوردی

اگر نسخهٔ قبلی (با داشبورد و فهرست لاگ‌ها) مستقر است:

| نسخهٔ قبلی | این نسخه |
|---|---|
| داشبورد آمار، فهرست لاگ‌ها، صفحهٔ ساختار | حذف شده — Grafana و ELK |
| `aggregate` برای نمودارها | حذف شده از دروازهٔ داده |
| صفحه‌بندی keyset روی فهرست | لازم نیست؛ فهرستی وجود ندارد |
| یک فایل `config.yaml` | دو فایل: `config.yaml` + `config.json` |
| ماسک همیشه جزئی | پروفایل قابل تنظیم، پیش‌فرض `secretsOnly` |

گام‌ها:

1. `config/config.json` را از این بسته بردارید و برچسب‌های خودتان را
   اضافه کنید.
2. سرویس را با همان `MONGO_URI` قبلی بالا بیاورید.
3. `ops/indexes.js` را اجرا کنید — احتمالاً می‌گوید کاری لازم نیست.
4. ایندکس‌هایی که فقط برای داشبورد قدیمی ساخته شده بودند
   (`status:1,startDate:-1` و مانند آن) دیگر استفاده نمی‌شوند؛ حذفشان با
   DBA است و این سرویس به آن‌ها دست نمی‌زند.

## پایش این سرویس

| نشانه | معنا |
|---|---|
| `readOnly.blockedWriteAttempts > 0` | 🔴 تلاش برای نوشتن — فوری بررسی شود |
| `searchFields.problems` غیرخالی | 🟡 فیلدی بدون ایندکس فعال شده |
| `labelWarnings` غیرخالی | 🟡 `config.json` مشکل دارد |
| `mongoOperations > 1` در پاسخ `/log/{id}` | 🔴 قید طراحی شکسته شده |
| `MongoExecutionTimeoutException` در لاگ | 🟡 جستجوی پیشرفتهٔ سنگین |
